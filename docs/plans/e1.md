# E1 交付计划

方法见 `evidence-first-project-workflow`。[S1 的 E1 子卡](../scenarios.md#e1-s0-06-真实双格)记录已通过的真实验收。

1. 锁定数据原件、pi 接口和 v6 分组。先用公开边界测试钉住坏输出、答案冲突、两格证据回读和依赖方向。
2. 建立六类契约。模式和身份进 manifest；对话是证据 ID 的原件，调用尝试是失败定位的原件。
3. `Models` 管调用策略，教师 Agent 管教学阶段，编排器管轮次。离线只换 provider。随后用独立根目录执行 E1 并审查。
4. 单独估算真实费用并请求授权；未获授权不能运行。四种坏教师全量自检、改进对照不是 E1 的实现范围。

吞吐检查点：先让一条 `node --test` 路径同时证明输出校验和证据回读；不为 E1 建排队、数据库或旧架构兼容层。状态与证据索引见 [status](../status.md)。

检查点：红测先覆盖新入口。独立审查复现证据分组重叠和未结束响应，两条回归转绿后重跑离线 E1。真实双格随后完成，当前进度见[状态](../status.md)。
