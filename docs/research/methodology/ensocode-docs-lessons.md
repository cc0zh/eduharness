# 用通用方法重写 TeachArena

先读 [通用方法论](general-methodology.md)。本文引用其中 M1–M7；每个编号可回到固定提交的 EnsoCode 原文、摘录、执行步骤和适用边界。本文是应用建议，不是已实现状态或评测结果。

TeachArena 的主线是：教师 = 模型 + harness；尺子告诉改进者一次改动让教学变好、变坏还是没变化，并指出哪一段对话、哪类教学行为支持判断。它不负责排名。重写不改数据集，只记录原有身份、版本及划分。先稳定项目，使一次运行产生能复核的报告和可用工具；再做改进循环；最后交付独立改进环境。

## 新仓库第一版骨架

这是提纲，不先创建空目录。命令名是建议，实施时以 CLI 契约为准（M3、M7）。

| 项目 | 存在的理由 |
| --- | --- |
| `README.md` | 说清目的、不排名、环境要求和一条无凭据的冷启动命令。让接手者读到第一份报告，而不是只知道怎么安装。 |
| `AGENTS.md` | 放默认权限、改动边界、查阅顺序和交付证据，避免冷启动依赖会话记忆。详细规范只链接。 |
| `docs/scenarios.md` | 为当前要验证的六栏场景给稳定 ID，作为实现、测试、文档和结项的共同入口（M1）。 |
| `contracts/` | 按 `core`、`dataset`、`teacher`、`learner`、`judge`、`artifacts` 六类归属存放契约。每类的 schema、说明、示例和契约测试放在一起，便于按同一边界维护和版本化（M2、M3；见架构决策 2）。 |
| `docs/runbook.md` | 写冷启动、授权真跑、离线复核、故障定位和产物清理步骤；不重复参数表和默认值（M3、M4）。 |
| `docs/status.md` | 只做路由：活跃卡和计划、最后一份已核验收据、仍缺什么。当前配置、通过范围和报告数值分别由配置、收据和报告维护。无有效收据就标未验证（M2、M3）。 |
| `docs/plans/`、`docs/history.md` | 跨模块工作才建活动计划。历史按变更记录版本、决策、结果、证据及未决项；需要保留全文才移入历史，不维护两套状态表（M6）。 |
| 锁文件、版本化配置、schema、测试和 CI | 机器读的默认值与契约在代码和配置中维护。仓库固定离线验证入口，真实运行另约授权；不是再造一个文档治理框架（M2、M5、M7）。 |

### `AGENTS.md` 指令提纲

- 先读 `docs/status.md` 和任务对应的场景卡，再读契约或运行手册。理由：短入口够完成一次冷启动，不复制规范。
- 默认读和离线验证。真实模型费用、凭据、保留集、外部写入或正式结果的采纳，按明确授权执行。理由：Agent 能自助查证，但不会把可调用误作获授权。
- 改行为先更新场景卡，写归属和非目标。所有教师、学生、裁判调用都走同一个 pi-ai 边界；不为单个入口另建客户端和默认值。理由：让改动落在根因所在处。
- 只在分配的工作区改允许的文件；数据集不变，改进尝试不能同时改尺子。产物交给 CLI 写到指定根目录，默认不入 Git。理由：保护比较口径与目录边界。
- 交付给出卡 ID、命令、运行模式、退出状态和可读回的原件；未跑真机就标明。理由：没有证据的「已完成」不能改变当前状态。
- 复发问题先在归属层补回归；能确定判定的错误再进离线 CI。理由：不靠提示词提醒同一件事，也不为偶发问题加平台。

## 怎样把场景卡倒推成实现、测试和文档

以下是建议的首批卡，按阶段排，不是本次执行结果。「没变化」要求预定证据标准能支持无实质变化；不能把样本不足、裁判失败或结果不稳定默认为没变化。

| ID | 谁 | 条件 | 能完成什么 | 证据 | 失败可定位 | 不算交付 |
| --- | --- | --- | --- | --- | --- | --- |
| S1 冷启动 | 新接手者 | 干净副本、空运行目录、固定输入、无 API 凭据 | 从 README 一条命令跑完整离线链路，再离线复核 | 退出状态、`mode=offline` 的收据、带 `messageId` 的报告、命令未发起模型请求的检查 | 坏输入、轨迹、证据引用或产物写入 | 单测绿、只能在原机器跑、手写报告 |
| S2 一次真实运行出报告 | 维护者 | 已授权预算，固定开发样例和配置，三个角色均走 pi-ai | 一次命令获得轨迹、裁判证据和可信报告；异常则产出可定位失败记录 | runId、数据/协议/harness 指纹、每角色模型和有效选项、可回读引文、离线复核结果 | 角色、案例、轮次和失败类别；能区分空正文、截断、传输失败、结构校验失败 | 只启动、手工拼补报告、重打分冒充独立样本、漏样仍报成功 |
| S3 尺子自检 | 评测维护者 | 固定尺子、开发样例、预登记映射与通过准则、真跑获授权 | 四类坏教师给出可诊断的负对照；无法区分就暴露尺子的盲区 | `answer_dump`、`sycophant_close`、`lecture`、`no_teach` 各自的预期标签、消息引用和实际证据，按协议记录重复与缺测 | 哪类负对照、哪条义务、哪段对话没有响应 | 仅四者排序、均分或换评分口径把失败修绿 |
| S4 改动对照 | 教学改进者 | S2、S3 已满足各自准则，固定数据划分、模型、尺子、预算与比较口径，仅变更目标教学行为 | 读出变好、变坏、没变化或证据不足，定位差异 | 基准与候选运行指纹、配对对话与消息证据、覆盖与缺测、预定判定规则 | 定位到输入不匹配、教学行为差异、裁判失败或证据不足 | 只贴总分、改了多个变量却归因某一个、用单题 probe 宣称整体改进 |
| S5 独立改进环境 | 新启动的改进 Agent | 独立工作区、空运行根、无私人历史；只读查阅基线与数据，仅在分配目录可写 | 按稳定入口查状态、跑离线场景、读比较证据、提交可复核的改进建议 | 启动说明、固定基线、命令与证据收据、写路径审计 | 能区分无权限、缺依赖、基线失配、候选执行失败和证据缺失 | 靠 Maintainer 私聊传参数、需要打开旧会话、改了数据或尺子、产物落共享目录 |

**用 S2 倒推。** 「一次命令且证据可回读」要求 CLI 串起解析配置、运行、校验、产出和复核。调用失败也必须落一份可定位收据，但不能生成有效结论。对空正文和坏消息引用先写离线回归，确认预期失败再实现；离线固定输入走相同编排和报告代码，不用为模拟单开一套输出路径。`contracts/core/` 定义错误分类，`contracts/artifacts/` 定义收据和报告格式，`docs/runbook.md` 说明授权条件、执行和查看顺序。最后跑代表性真链路才验 S2，S1 通过不能代签 S2。

**用 S3 倒推。** 先登记四个负对照要暴露的行为，例如 `answer_dump` 直接交答案、`sycophant_close` 迎合并过早结束、`lecture` 单向长讲、`no_teach` 缺少教学介入。具体指标和阈值以新协议为准，不从这些名字推导分数。自检失败时查样例是否触发、行为是否出现、裁判是否给出匹配引文，区分尺子问题和坏教师没有发挥作用。S3 是灵敏度自检，不是正式改进证据，也不动保留集。

## 哪些做法让项目更快回到主线

- **先交一条薄路径（M1、M4、M5）。** 优先 S1，然后在得到授权时跑 S2，再做 S3。先让 CLI 对一条代表性对话跑完并能读回报告，而不是先做多后端、通用调度、可视化仪表盘或插件。单题只证明链路，不证明尺子或正式基线。
- **供应商共性用 pi-ai，项目策略只维护一处（M2）。** 固定 `@earendil-works/pi-ai` 版本，走公开接口；教师、学生、裁判以角色配置调用同一个窄边界。边界解析有效模型、输出预算与推理设置，记录实际参数及用量，统一分类空正文、截断和传输错误。用阶段 schema 校验结构化结果，并把契约失败与传输失败分开。只有现有库的重试行为查清、场景证明需要，才制定有次数和总预算的项目级重试；不叠两层盲重试，不因格式错误静默换模型或放宽契约。遇不支持的能力就给明确状态，不能靠换模型或默认值冒充同一对照。EnsoCode 的 [package.json](https://github.com/J3n5en/EnsoCode/blob/0a54bc0ba5686561c7595af3d599f648f916b5f6/package.json#L45-L51) 声明 `"@earendil-works/pi-ai": "1.5.1"`，仅作为依赖锁定的证据，不照抄版本，也不表示 pi-ai 会替本项目保证 schema、成本或教学质量。实现时查选定版本的公开 API，并按实际支持范围复检。
- **用最小自动检查代替反复拉齐（M5、M7）。** 本地和 PR CI 共用一条无模型检查入口，先守数据指纹、命令/schema 示例、错误分类、消息引用和报告可回读；逐次补真实复发问题。live 验收是显式授权的单独步骤。EnsoCode 的跨厂商验证适用于这里确实承诺跨厂商的契约，不要求每次教学改动付费跨跑；切换供应商不能替代固定条件的改动对照。

## 哪些做法让改进 Agent 可以独立工作

- **只读即可接手（M3、M6）。** `AGENTS.md` → `docs/status.md` → 对应卡和运行手册。入口说明当前基线的 commit、数据/协议/harness 指纹及证据位置；冷启动能用仓库内的小型脱敏 fixture 离线查阅。真实原件可以在受控存储，需要权限或不可见就如实说明，不依赖私有会话。
- **权威基线与候选工作区分开（M2、M4）。** 冻结数据、尺子和基准配置。给改进 Agent 独立候选工作区和运行根，而不是写基线。工具先提供 `status`、`inspect`、`compare` 一类只读结构化接口；联网、模型费用和写权限另授。目录和权限要由工具约束，不能只写进提示。独立环境放在改进循环可复核之后，不为第一版实现通用插件或远程部署。
- **一个运行根，一个证据链（M4、M7）。** 例如 `<run-root>/<runId>/` 下放 `manifest.json`、`trajectory.jsonl`、机器报告、可重建的 Markdown 和 `receipt.json`；`runId` 由程序生成，暂存失败也在同一次运行下记录且不覆盖成功原件。版本化的是 schema、配置、脱敏 fixture 和必要的已核验索引，不是所有模型输出。显式传根目录，限制写入边界；报告生成与离线复核按标识回读，不靠全局路径。收据区分完成、失败、超时和不可评估，正式采纳由独立记录承担，不能从报告存在推断。

## 架构决策 1：LLM 调用层

状态：已决定，待实现与验证。适用于新仓库，不描述旧仓库现状。

### 背景

教师需要维护教学阶段、调用工具并留下行为证据。学生模拟器、裁判和复评只需要取一次完整回复，再校验结果。旧仓库在多条调用路径上反复修预算、推理设置、结构化输出、重试和遥测；重写应让这些策略有唯一归属，同时保留各角色所需的调用方式。

### 决定

- **教师使用 `@earendil-works/pi-agent-core` 的 `Agent`。** 用 `thinkingLevel` 设置推理档位，用 `thinkingBudgets` 为支持按 token 配置的供应商设置思考预算，不假定每个端点都会执行相同的 token 上限。提示词分段对应 system message 的 `sections`，教学工具对应 `tools`，教学阶段的推进与结束在 `finishTurn` 中根据当前状态决定。`finishTurn` 只调度教师 Agent 内部的下一次请求或结束，不负责把话权交给学生；不得无条件返回 `continue`。
- **内部状态与学生可见对话分开。** 用自定义消息类型保存教学阶段、评测标记等内部信息，`convertToLlm` 按白名单过滤或转换进入教师模型的消息。给学生模拟器构造输入时，另从公开对话投影取消息，不传教师的完整 transcript、系统提示、内部工具结果或证据日志。`convertToLlm` 本身不是学生侧的隔离边界。用 `beforeToolCall`、`afterToolCall` 和 `Agent.subscribe()` 的事件流记录教学行为证据，并按轮次、消息 ID、工具调用 ID 关联请求、拦截和结果。
- **学生模拟器、裁判和复评使用 `@earendil-works/pi-ai` 的 `Models.completeSimple`。** 在本地解析 JSON 并按各角色的 schema 校验。校验失败最多重试两次，即初次请求加至多两次重试，均计入同一预算；耗尽后显式报告失败，不放宽 schema，也不切换模型。传输错误、空正文、截断和 schema 失败分别记录，不把前几类统称为 JSON 校验错误。
- **TeachArena 维护师生轮转。** 编排器决定双方何时发言、何时结束以及何时进入裁判阶段。`agent-core` 只管理单个教师 Agent 的消息、工具和内部请求循环。
- **所有模型请求共用一个入口。** 项目只在调用层构造一个 `Models` 实例。调用层包装 `Models.streamSimple`，教师通过 `Agent.streamFn` 注入该包装；同一调用层的单次入口直接调用同一个实例的 `Models.completeSimple`。两种调用共享有效配置、预算、重试策略、日志字段和错误分类，不串联调用两个 SDK 方法，也不在角色或编排器中再包一层重试。教学策略只声明角色参数和校验契约，调用层负责执行并记录实际参数与每次尝试。

### 理由

复用 `Agent` 可省去自建教师工具循环，同时把提示词分段、工具和教学阶段保留为独立的改进对象。对不需要工具循环的角色，`completeSimple` 和本地校验更直接。上游 README 的严格 JSON Schema 约束采样支持列表针对工具调用，未列出 DeepSeek 和 OpenRouter；因此不把严格结构化输出当作这两个端点的共有能力，也不据此断言它们的所有模型都无法生成 JSON。单一调用层让不同角色使用适合的 SDK 入口，而预算和运行证据仍然用同一口径。

### 放弃的方案

- 用 `pi-ai` 给教师手写工具循环。会重复实现工具调度、上下文转换和事件采集。
- 把学生、裁判和复评也包装成 `Agent`，或让 `agent-core` 控制师生轮转。会增加不需要的循环状态，并模糊课堂轮次和 Agent 内部轮次。
- 依赖供应商的严格结构化输出，或每个角色各写一个调用适配器。前者无法作为当前端点组合的统一保证，后者会重现策略漂移。

### 后果

TeachArena 仍负责轮转、阶段规则、本地 schema、消息投影和证据持久化。实现时用 S1 的离线回放验证内部标记不会出现在学生输入、重试不会超过上限、工具事件能关联到消息；再在获授权后用 S2 核对模型实际选项、失败分类和原件。数据契约在新仓库落地时按归属进入 `contracts/`，预算、推理和重试留在调用配置中；本节不代表实现或评测已经完成。

### 风险

pi 的 API 迭代快。精确锁定 `@earendil-works/pi-agent-core` 与 `@earendil-works/pi-ai` 版本，在评测身份及运行 manifest 中记录实际版本。升级任一包都按更换尺子处理：重跑边界回归与基线，同版本内才作正式改动对照；升级前后差异不得直接归因于教学改动。另需通过回归防止 `finishTurn` 无限续跑、内部消息泄露和重试预算叠加。

## 架构决策 2：契约按归属边界分开存放

状态：已决定，待实现与验证。适用于新仓库。

### 背景

教师是被测对象，裁判维护尺子，两者有不同的消费者和版本节奏。按文件类型将同一契约拆到 `schema/`、`docs/` 和 `tests/`，既容易漏改，也看不出谁可以读取答案键和评分规则。

### 决定

按谁产出、谁消费、谁负责版本、为什么会变来划分边界。每类在同一目录维护机器可读的 schema、说明、示例和契约测试。schema 是数据形状与字段约束的唯一来源；说明解释语义和兼容性，示例和测试用该 schema 验证，不另写一份字段定义。公共字段只在 `core` 定义一次，其他类引用它。

| 目录 | 契约范围与版本归属 |
| --- | --- |
| `contracts/core/` | 共享最底层：ID、消息格式、遥测记录、错误分类。共享格式和语义变化由 `core` 维护。 |
| `contracts/dataset/` | 题目和答案键，随数据集版本管理，只供评测侧使用。编排器只把允许公开的题目内容投影到教师输入，不给教师数据集对象或答案键。 |
| `contracts/teacher/` | 被测 harness 的输入与输出，由教师 harness 维护，随 harness 版本走。 |
| `contracts/learner/` | 学生模拟器的状态和输出，由学生模拟器维护。 |
| `contracts/judge/` | 评分规则、逐轮和轨迹输出、证据引用规则，由评测侧维护，随评测身份走。 |
| `contracts/artifacts/` | 运行清单、结果、收据和报告，由运行与报告层维护。通过 ID 和版本引用相关记录，不复制上游契约。 |

预算、推理和重试是调用配置，不纳入契约目录。收据可以记录实际生效的配置或其指纹，但不负责定义策略。

### 理由

默认每个非 `core` 类只能依赖 `core`；`core` 不依赖其他类。唯一例外是 `judge` 可只读引用 `teacher` 的输出契约和 `dataset`。依赖不会反过来：`teacher` 不得依赖 `judge` 或 `dataset`，也不得经编排器、工具、配置或共享模块接触答案键或评分规则。裁判可以读被测输出，教师不必随尺子改版而变化。

### 放弃的方案

不按文件类型建立横跨所有领域的 `schema/`、`docs/`、`tests/` 三套目录，也不让所有契约共用一个版本。首版保留六类；只有其中一部分开始独立变化、需要独立维护或版本化时才继续拆分。

### 后果

新仓库用依赖允许清单做边界检查，接入本地离线检查与 PR CI。检查覆盖源码导入和 schema 引用，并通过实际解析目标识别绕经别名或重导出的违规依赖。失败信息指出来源、目标和允许的依赖方向。另用契约测试检查教师可见输入与工具权限：导入检查不能替代运行时数据隔离。

### 风险

`core` 容易变成杂项目录，只收语义一致、确需共享的字段。教师输出格式变更可能影响裁判，应使用对应版本的示例检查兼容性，并记录 harness 与评测身份的配对，避免把契约变化误当作教学改进。
