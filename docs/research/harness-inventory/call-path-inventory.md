# TeachArena 模型调用路径盘点

## 结论与证据范围

多条调用路径确实增加返工，但现有证据不支持它是推进慢的主要原因。最近四个症状涉及 **2 类跨独立实现的重复修复**：输出预算、停止原因和用量遥测。每类涉及教师 TS 和评测 Python 两处，共 **4 个能力×实现落点，超过每类首个实现的额外落点为 2**。推理参数映射、学生 JSON 尾随文本不另算跨实现重复。最明确的交付瓶颈是**还没有一把经过验证、能在固定身份下稳定给出有效分数的尺子**，不是已经测出的工时或延迟主因。下文给出分母、归类和反例。

代码基准为 `feat/trajectory-evidence-v2@e6b17a150218f5abeea5782fc02742bc6dc6290c`。该提交的路由默认与本机实际设置分开列。`T` 代表只读查看的 `.cache/tau2-bench/src/tau2`，`L` 代表 `.cache/tau2-bench/.venv/Lib/site-packages/litellm`。缓存行号说明本机安装的代码形状，未执行锁一致性检查。tau2 锁定提交是 `c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4`，仓库登记了 `llm_utils`、UserSimulator、Orchestrator 的锁和覆盖规则（`eval/teacharena/lock.json:83–110`）。历史运行仅引用已提交的审计与历史文档，不读取 `runs/`、原件目录或密钥值；不运行测试、评测、一致性检查或模型调用。配置不是调用原件，SDK 入参也不是 HTTP 原件。

## 5. 共用管道时保留独立的尺子

1. 将版本化 transport 输入限制为规范化消息、工具定义（适用时）、角色、模型路由、预算、schema 描述和 attempt 计划。输出是正文、原始终止字段、用量、错误/尝试记录。角色分别传入自己的配置，不共用会话、上下文、密钥、缓存命名空间或结果对象；复用客户端代码不等于使用相同模型或共享数据。现有分角色配置和来源保留见 `src/cli/settings.ts:50–74`、`src/eval/profile.ts:55–67,95–116`。
2. `TutorSession` 独占教师指令、工具、修订和记忆；学生独占画像、保真与状态更新；裁判独占 rubric、消息证据及分数契约。传输能判断空正文或 `length`，不能替角色判断教学是否正确或把缺失纳入分母（`src/agent/tutor-session.ts:138–185`、`learner_simulator.py:216–245,251–284`、`trajectory_evidence.py:249–298`、`docs/design-docs/EVALUATION.md:84–91,105–111`）。共同 provider 可造成相关误差，不能把独立角色当作独立测量；任命第二裁判仍应显式选端点并记录。
3. 每个 run 固定教师 fingerprint、评测版本、lock、profile hash、角色模型/端点指纹和有效环境。提议再记每角色 `transportVersion`、`policyHash`、effective cap、首发和重试 reasoning、格式与 strict、每次请求终止及原始字段来源；不保存密钥或推理正文。参数支持被拒要明示，不静默降级；运行中禁止按错误切模型、策略或尺子。老师 A/B 只动被测配置，学生和裁判的角色 policy hash 保持一致。身份保存与恢复检查见 `src/eval/run.ts:219–259,385–396`。
4. 复评只借用轨迹、固定学生身份，不生成新的教师独立重复；源与新尺子 ID、源和新裁判用量、来源轨迹/配置/结果哈希分开。不同策略之间的对照先做固定证据重放和独立语义复核，若会改有效性或评分就是新尺子，需另起完整网格（`src/eval/rescore.ts:210–232,292–309,319–353`、`docs/design-docs/EVALUATION.md:124–136,180`）。

## 6. 为什么推进慢，下一步该决定什么

按已提交审计，v3 的 7 个最终基础设施故障，**确认由输出耗尽造成的是 0/7**。四格调用前路由失败；剩下三格分别是学生状态引文、学生生成 JSON、保真判断自相矛盾；其中一次早期裁判失败并非最终故障原因（审计 `:18`）。另外确实有后来的 HY4 推理耗尽及教师频繁撞 cap，说明调用管道值得修，但不能用不同时间、不同分母的数据把它们加成项目慢的比例。按已提交计划，v4 十格 `1 valid/8 partial/1 infra`，v5 的同源复评是 `3 valid/6 契约故障/1 非 scored`，四组仍不可评估。最大**可定位**阻塞是固定尺子下仍缺干净的完整分数、独立语义校准和足量独立重复（`docs/exec-plans/active/2026-11-17-small-real-baseline.md:5–13`、`docs/CURRENT_STATE.md:8–11`）。无工时账或受控对照，不声称已经量化某因素对进度的因果贡献。

建议先拍板 **B 的第一阶段和尺子冻结**：明确需要的遥测/身份、锁定当前 route/profile/策略，并单独批准固定六断言的语义复核和同一身份 sanity 网格。第一阶段约 1–2 人日，可回滚，不在这个阶段迁教师或调学生。**C** 适合眼下只想解一个可复现缺口，约 1–3 人日，易回滚但重复实现照旧。**A** 仅当 B 后仍有持续的跨实现故障、且愿意重做等价证据与定标时采用，约 8–15 人日，需整版回滚，影响教师及评测两边身份。付费运行、模型/端点调整和是否采用新尺子应各自决定；本次未做。
