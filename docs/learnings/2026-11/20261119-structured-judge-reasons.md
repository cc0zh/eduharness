# 裁判理由不能只回显分数

**现象。** S1 的 v3 冻结补评中，正常格裁判连续三次返回合法 JSON，但六维 `reason` 都只回显分数，例如 `agency_handoff.reason: "1"`。本地拒绝全部三份响应，未出分。

**根因与边界。** 已证实旧传输格式把解释和消息引用都留在自由文本里，没有独立的必填理由引用字段。判决满足字符串类型，却没有解释或可回读引用。未证实模型为何只回显分数；理由中包含数字本身不是错误。

**证据。** `3125adb:docs/status.md:73` 和 `runs/s1-v3-frozen-real-20261119-01/normal/calls/judge-4-1-{1,2,3}.json` 保留三次失败。[原件回归](../../../test/judge-real-replay.test.mjs)第 155–178 行核查空理由、裸数字和未声明的引用。`10654a7` 改输出契约；`20c7056:docs/status.md` 和 `runs/_receipts/s1-v3-output-v2-frozen-real-20261119-01.process.json` 记录补评。

**修复或现状。** `judge-output-v2` 每维必填非空的 `evidence` 序号数组，本地还要求 `reason` 有解释且其 `#N` 引用都在该数组内。冻结原对话不变，补评五格均在首个裁判尝试拿到有效分；`sycophant_close` 仍同档，这次补评不算整体验收通过。

**预防。** 在结构中声明要引用的证据，完整校验解释和引用的对应关系。回放原败例，也测有引用但没有解释的响应。合规引用是否支持定档，仍需回读消息。
