# 执行环境：费用确认入口要按当次核实

**现象。** 第 4 步进度文件先记 `ask_user` 不可用，于是完成零请求预检后停在费用门槛；同一份记录随后记下通过 `ask_user` 获得授权，再启动三侧真实运行。

**根因与边界。** 已证实前一检查点没有记到本次费用确认，不能发真实请求。进度文件能证明当时如何判断，不能证明无人值守普遍禁用该工具，也不能证明中间宿主能力变了还是初判有误。

**证据。** 本机 `.tmp/scratch/harness-ab/progress.md:14,43–53`。`runs/harness-ab-v1/baseline/_receipts/harness-ab-v1-baseline-estimate.process.json` 显示 0 请求，`harness-ab-v1-baseline.start.json` 是后续真实启动。确认要求见 [AGENTS.md](../../../AGENTS.md) 与[运行手册](../../runbook.md)的第 4 步。

**修复或现状。** 确认后只执行已登记的范围，未改预登记、运行 ID 或预算。项目的事前确认规则不变。

**预防。** 按本会话提供的能力判断确认入口。能用时按规则报本次调用数和 token 上限；不能确认时只暂停付费步骤，保留恢复点，继续不发请求的工作。不要把另一会话的提示当成通用权限，也不要用 `--confirm-cost` 绕开确认。
