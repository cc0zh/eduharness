# 交权后核对验证机会落在哪一轮

**现象。** 阶段 3 v2 的候选在三个 V 由 2 到 0 的格都在 #6 交权，但基线 V1 引用分别在 #4、#8、#6。把三格都说成「固定句直接挤掉验证」会错认两格。

**已知原因与边界。** 候选的状态动作替代线性推进。同一轮只能发一个公开教师回复。F18-A／伸手的第 3 轮，基线请学生改变中间值验证中位数，候选只请自行检验，学生重算了原题。另两格变化发生在不同轮；两臂前序和后续都不相同，不能定出固定句的单独效应。

**证据。** `stage3-dev-v2-real-01` 的 [F18-A／伸手 B 原话](../../../runs/stage3-dev/stage3-dev-v2-real-01/baseline/TA2B-F18-A/answer-seeker/transcript.json)与 [S 原话](../../../runs/stage3-dev/stage3-dev-v2-real-01/candidate/TA2B-F18-A/answer-seeker/transcript.json) #6–#8；双方 V 判定保存在各格 `calls/judge-4-6-1.json`。[三格原文与动作对照](../../research/stage3/closeout.md#五项归因核实)

**处置与预防。** 变体不采用。下一次检查交权不能只数动作，要分别追踪两臂 V1 的机会、下一条学生证据和候选动作。把「交权时能否保住概念验证或近迁移」登记为待测假设。
