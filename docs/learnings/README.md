## 目录与命名

用 `docs/learnings/YYYY-MM/YYYYMMDD-topic-slug.md` 写 Markdown 速记。日期取事件或决定的证据日期。每篇只记一个知识点，写完登记到上表。不另编流水号，修复或现状写在条目里。格式参照旧库 `mini-eduharness2/docs/learnings/README.md` 和 `WRITING_GUIDE.md`。

## 触发与编写

- 由改动者或运行负责人起草。在排障定性、修复收尾或阶段验收时写，提交前由审查者回读出处。能挡住误判的做法也值得记。
- 写清现象、根因、证据、修复或现状、预防。把已证实的直接原因与仍待验证的假设分开。处置有效不代表根因已查清。
- 最少给一份可定位、可回读且支持结论的原件。代码用提交及仓库路径和行号；评测用 run ID、原件或收据路径，必要时加格子、尝试序号或消息 ID。只存在本机的材料要注明位置，另给可提交的索引或契约出处（如有）。只有转述、没有原件就不入册。改写旧库知识须标明旧出处，并用本库原件核实适用范围。
- 旧库 `npm run check:docs` 检查本地链接与目录索引，不判断结论真假。本库暂不移植。若索引漏登反复发生，再考虑加一个目录收录与链接检查及其正反例测试；现有 `npm run check` 的 M7 检查保持不变。
